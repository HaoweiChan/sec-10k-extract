R14 — the BODY_MAX adjudication, VERIFIED before publishing
========================================================================
The coordinator's suggested framing was that 700 'sits above every observed
value in both dev and held-out'. I checked that FIRST and it is FALSE — the
page-pointer candidate pool at any length runs to 1,010,422 chars (jpm-2024
item 15). BODY_MAX is a stub cutoff, not an upper bound. The claim actually
supportable is a plateau argument, and here is the measurement:

   dev: nearest below 700 = 629 (intc-2002 item 5); nearest at/above = 805 (ibm-1997 item 5)
   dev: plateau containing 700 = 630..805
  held: nearest below 700 = 247 (mrk-1995 item 7); nearest at/above = 738 (mrk-1995 item 8)
  held: plateau containing 700 = 248..738
VERDICT, and it is NOT the clean story I was handed:
  * The plateau around 700 is bounded on BOTH sides by DEV values (629
    intc-2002 item 5, 805 ibm-1997 item 5). Every bound in 630..805 gives an
    identical dev result. Nothing held-out defines that interval.
  * Held-out's own plateau is 248..738 — much wider, so it cannot be what
    pinned 700.
  * Exactly ONE held-out span sits inside the dev plateau: mrk-1995 item 8,
    738 chars. Its body:
      "ITEM 8.  FINANCIAL STATEMENTS AND SUPPLEMENTARY DATA.\n\n     (A) FINANCIAL STATEMENTS\n\n     The consolidated balance sheet of Merck & Co., Inc. and subsidiaries as of\nDecember 31, 1995 and 1994, ...
    -> an EXTERNAL-document pointer, which the class rule already rejects for
       its siblings 5 and 7. So even at the top of the plateau it changes no
       published figure.
  * The constant was written once and never revised:
      4ecc1e5 D9: rule on the internal-pointer class and the combined-heading fan-out (ADR-034)

WHAT DOES NOT FULLY CLOSE, published rather than hidden: the dev plateau runs
to 805 while held-out is unchanged only to 738. A different in-plateau choice
(780) would have admitted mrk-1995 item 8 as a CANDIDATE — then rejected it,
changing no number. So 'any in-plateau value is equivalent' is true of D9's
CONCLUSIONS, not of the candidate list. Recorded in README and §g.
