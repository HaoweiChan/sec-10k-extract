escalate-default-on — the money checks, re-pinned and re-proved
================================================================

Owner instruction, 2026-08-27: "make it default on, remove the button". The
deployed inspector escalates on every request; the escalate checkbox, the
helper that read it, the /api/meta arming round-trip and the request-level
`escalate` flag are gone. `extract_items`' own `escalate=False` default is
UNCHANGED — flipping it would put paid calls on every `python3 -m evals.run`
and in CI. ADR-036 §h2 carries the decision and the exposure it creates.

Four checks pinned the removed behaviour. None was deleted to make the gate
pass; each was re-pinned to the NEW property and then falsified, because this
repo's recurring defect is a safety mechanism nobody bound.

  escalation_locks   was: arming is `os.environ.get(VAR) == "1"` (Eq, "1").
                     now: the same expression is the operator's OFF switch and
                          must be `!= "0"` (NotEq, "0") — never a constant —
                          and, NEW, the `extract_items(...)` call site's
                          `escalate=` must NAME `ESCALATION_ENABLED` rather
                          than a literal, because with no request flag left to
                          AND against, `escalate=True` would orphan the switch.
                          Both ceilings, their env vars, their bounded
                          defaults, the single Budget built from the two NAMES
                          and the server_budget() call are untouched.
                          M1-M7 below.
  routing_provenance was: the #escalate checkbox ships unchecked and enabled,
                          the page asks the server whether it is armed, the
                          box is disabled when it is not, the refusal is
                          rendered, and the flag rides two named wires.
                     now: six ABSENT-pins — no control, no helper reading one,
                          no `escalate` flag on any wire, no arming round-trip,
                          no `escalation_disarmed` note (the server no longer
                          emits it, so rendering it is a dead honesty
                          mechanism). The eight routing-strip pins are
                          unchanged and are now the ONLY honesty the page
                          owes the viewer. M8-M10 below.
  WIRE_API           was: two pins — `armed = escalate and ESCALATION_ENABLED`
                          plus the call carrying `escalate=armed`.
                     now: one pin — the call carrying `escalate=
                          ESCALATION_ENABLED` and the process budget. There is
                          no request-level flag to gate, so there is no gate
                          expression. M6, M7.
  WIRE_UI            was: the fixture and url bodies carry `escalate:
                          escalateOn()`.
                     now: they carry the two display flags only. M8.

Method: one mutation at a time on the shipped tree, `python3 -m evals.run
--suite invariant` run unpiped and read by EXIT CODE, then restored and re-run.
Every mutation exits 1; every restore exits 0. The check messages under each
run are the checks' own output, which evals.run summarises away.

The mutation runs' report artifacts and their history.jsonl lines are not
committed: they are runs of a deliberately-broken tree, not of this branch.
This file is their record.
